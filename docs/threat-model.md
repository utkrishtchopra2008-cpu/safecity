# SafeCity MVP threat model

This is a focused threat model for the current single-institution modular monolith. The backend is the authorization boundary; Supabase Storage is private; TinyFish receives only allowlisted public context. It does not claim a third-party penetration test or live Supabase policy validation.

| Threat | Control and negative proof | Remaining limit |
|---|---|---|
| Account/session theft, expiry, revocation | Hashed server-side session tokens, HttpOnly cookie, CSRF secret; `backend/tests/test_auth.py` covers logout revocation plus expired/revoked-token rejection. | No MFA or account recovery contract is specified. |
| Broken object authorization / role bypass | Role checks on protected routes and resource lookup before evidence response; `backend/tests/test_auth.py` checks unauthenticated incident/evidence/job routes and operator denial for source mutation. | The schema is single-institution and has no tenant/source membership rule; live object-level policy remains unverified. |
| CSRF | Origin and token validation on unsafe session-authenticated requests; `backend/tests/test_auth.py` tests missing token and attacker origin. | Deployment origin/CORS values must be configured correctly. |
| Upload/parser abuse and resource exhaustion | Streaming byte cap, signature/MIME/extension checks, duration/resolution/frame checks and first-frame decode; `backend/tests/test_video_uploads.py` tests over-limit and bad signatures; `backend/tests/test_worker.py` and `test_opencv_models.py` cover bounded processing behavior. | Broader codec/corruption, cancellation and production resource characterization remain incomplete. |
| Malicious client filename/path traversal | Only the validated suffix is used and the staged path is server-generated; `backend/tests/test_video_uploads.py::test_client_path_in_filename_is_never_used_for_staging_path` verifies path-independent staging. Storage keys are generated server-side; `backend/tests/test_supabase_storage.py` rejects traversal keys. | Full live storage object ownership is unverified. |
| Secret/configuration exposure | Backend-only secret settings, ignored `.env`, masked TinyFish key setup, safe error categories; `backend/tests/test_auth.py` asserts login never returns session tokens; `backend/tests/test_tinyfish.py` asserts API key is only in the provider header and provider failures are normalized. | Automated repository-wide secret scanning is not configured. |
| Signed storage URL leakage | Private bucket and short-lived (120-second) signed URLs with `no-store` and `no-referrer`; `backend/tests/test_supabase_storage.py` checks private signing behavior. | Live bucket policy and browser referrer behavior were not tested against Supabase. |
| Prompt injection / unsafe external text | Provider content is bounded typed data and frontend rendering uses React text interpolation; `frontend/src/pages/PublicContextPage.test.tsx` verifies HTML-like provider text renders as text with no injected element. | Human operators may still misinterpret misleading public content; UI labels its provenance and role. |
| SSRF, redirects, private-address access | HTTPS, allowlisted host, public-address/credential/query validation, redirects disabled and returned final URL revalidated; `backend/tests/test_tinyfish.py` covers local/private/credential-bearing/redirect URLs. | DNS rebinding behavior inside TinyFish is provider-controlled and not observable by this client. |
| Excessive external usage | Login, source creation/upload/processing, evaluation creation and public-context operations have bounded in-process limits; `backend/tests/test_auth.py`, `backend/tests/test_rate_limit.py`, and `backend/tests/test_tinyfish.py` cover limit behavior and response caps. | Limits reset on restart and are per-process; cross-instance enforcement requires the documented trusted-proxy/shared boundary. |
| Deletion/audit integrity | Append-only DB audit trigger is exercised in `backend/tests/test_postgres_integrity.py`; orphan cleanup is dry-run by default and `backend/tests/test_storage_cleanup.py` verifies age filtering/reference rechecks. No automatic evidence retention/deletion period is invented. | Live Supabase cleanup and destructive user-requested evidence deletion are not implemented; job cancellation is not specified by API.md. |

Before shared deployment, configure HTTPS, secure cookies, backend-only database/storage credentials, exact CORS/CSRF origins and private bucket policies. Run the opt-in PostgreSQL suite with a disposable database and validate Storage policies in a non-production Supabase project. Do not use this checklist as proof of production security.
